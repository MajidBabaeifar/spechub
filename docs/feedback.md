# Feedback

Specfork is young, and what you tell us shapes it. All of these go to the maintainers; you need a GitHub account.

- **[Give feedback](https://github.com/specfork/specfork/issues/new?template=feedback.yml)**: what works, what doesn't, what you'd like.
- **[Request a spec](https://github.com/specfork/specfork/issues/new?template=spec-request.yml)**: an app or tool you'd like a recipe for.
- **[Report a problem with a spec](https://github.com/specfork/specfork/issues/new?template=spec-problem.yml)**: a requirement that is wrong, unclear or missing. Every spec page has a link that fills in the spec's name for you.
- **[Discussions](https://github.com/specfork/specfork/discussions)**: questions, ideas, and showing what you built.

Built an app from a spec? Tell us in Discussions, and [list your implementation](publish.md) on the spec's page.
